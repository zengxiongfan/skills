# 坑清单（req-selftest-report reference）

> 实战教训，每条都真实踩过，代价已付过一次，别再付第二次。

## 截图解析

1. **`截图!A{n}` 与图片锚点差一行**：图片的锚点起始行通常是 n（引用行）或 n+1。只取其中一个会大面积错配——实测 125 个引用里，绝大多数是 n+1。解析必须"n 或 n+1，再兜底覆盖区间"。
2. **同一张图被多个案例共用**（如一份截图同时覆盖"新增/修改/查询"三个页面）：报告里第 2 个案例不要再嵌同一张图，标"（执行截图同上）"。
3. **案例有引用但截图表里没有图**：换同组备选案例；换不了就标"（执行截图待补充）"，别拿相近的图凑。
4. **无引用模块的隐藏图片不能猜配**：截图工作表里可能躺着几十张没人引用的图（做过实测：迭代二理算公式 109 个案例 0 引用、迭代三主文件"图1"表 95 张图无任何案例指向）。这类只能如实报告，不能按"顺序大概对应"去配。
5. **嵌入单元格图片解析不到**：本 skill 只支持浮动锚定图片（drawing/twoCellAnchor）。若测试同学插的是 Excel 365"放置在单元格中"的图片，需另写解析（提示用户换浮动图或提供导出图）。
6. **图片可能是 JPEG 伪装成 .png**：不按扩展名判断，直接按文件内容处理；组版时统一交给 python-docx，不预处理。

## 案例表解析

7. **列不一定固定**：同项目不同迭代的案例 xlsx 列名/列序/工作表名都会变（"输出"vs"预期结果"、"实际输出"vs"实际结果"、"截图"vs"截图对应行数"）。用同义词模糊匹配，且**精确匹配优先于包含匹配**（否则"输出"会把"实际输出"吃掉）。
8. **测试项是合并单元格风格**：只有每组第一行有值，后续行空——必须前向填充，否则分组全乱。模块列同理。
9. **案例编号列可能为空**（如"理赔管理"模块），选案时用行号或模块定位兜底。

## 报告生成

10. **案例编号不进正文**：`RCP-\d+-\d+` 一律剥离；表头的需求编号（`RCP-XXXX`）保留。
11. **模板 `1.1` 占位段落自带缩进**：改写成首节标题时必须清零 left_indent/first_line_indent，否则首节标题与其它节不齐。
12. **字体要同时设 eastAsia**：只设 `run.font.name` 中文会回退宋体；必须 `rPr.rFonts.set(qn('w:eastAsia'), '微软雅黑')`。
13. **字号单位是半磅**：模板 10pt 对应 `w:sz=20`；正文 10.5pt 对应 21。python-docx 用 `Pt()` 即可。
14. **图片宽度用模板可用宽度算**：内置模板 A4 + 左右各约 0.75cm 边距，可用约 19.5cm；固定 7000000 EMU（约 19.45cm）刚好放满。别用 7.5 英寸（会溢出）。
15. **页边距很窄是故意的**：历史报告就是 426/424 twips（约 0.75cm），不要"修正"成默认 2.54cm，否则截图装不下。

## 环境

16. **本机 `python` 可能指向 3.14**（无 python-docx/openpyxl/pywin32/fitz）：一律显式用 Python 3.10 解释器路径运行脚本。
17. **渲染依赖本机 Office Word**：Word COM（`DispatchEx('Word.Application')`）必须用 `ReadOnly=True` 打开，渲染完 `Quit()`，否则文件被锁、下次覆盖保存失败。
18. **visual-judge 可能供应商不可用**：不要因为它失败就跳过验收——按 `references/process.md` 阶段 5 的清单逐页自查。

## 内容口径（历史用户反馈）

19. **"理算计算逻辑"与"页面显示"的取舍不固化**：同一项目里，理算规则/梯度赔付处理这类纯计算模块不写；理算补充区域/理算公式这类页面展示要写。但每次迭代由用户给排除清单，skill 不自带判定表。
20. **无图模块的两种合法处置**：① 标"（执行截图待补充）"，用户事后补图；② 用"实际输出"列数据写纯文字描述（如跨保单累计的保费/案号/赔付金额）。二者都在交付说明里讲清楚。
21. **案例数不够时不要硬凑**：某模块只有 2 个带图案例就写 2 个，并在交付说明里注明"该模块仅 N 个带截图案例"。
