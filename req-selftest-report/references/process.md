# 完整流程细节（req-selftest-report reference）

> SKILL.md 是骨架与硬规则；本文件是 6 个阶段的完整动作、命令口径与验收清单。
> 所有命令假定工作目录为当前迭代的报告目录，脚本路径相对 skill 根目录。

## 阶段 0：自适应解析

### 0.1 先盘点，再解析

```bash
python <skill>/scripts/parse_cases.py --xlsx 案例A.xlsx [案例B.xlsx ...] \
    --out iter_data.json --export-images all_images
```

脚本行为：
1. 遍历每个 xlsx 的所有工作表，在前 15 行内找表头行（命中"模块/测试项/测试案例标题/截图对应行数"等同义词 ≥4 项）
2. 按同义词表认列（精确匹配优先于包含匹配，避免"输出"误吃"实际输出"）
3. 解析所有含 drawing 的工作表，得到每张图的锚点行区间（`from`/`to`，1-based）
4. 逐案例解析"截图对应行数"引用：
   - `截图!A65` / `图1!A65` → 指定工作表第 65 行
   - `A65` / `65` → 任意含图工作表第 65 行
   - 多值用 `、` `,` `;` 分隔
5. 引用行 → 图片：**起始行 == n 或 n+1**（差一行规则，两个都试）；都找不到再取"覆盖 n 的区间"
6. 测试项/模块空值前向填充（合并单元格风格）

### 0.2 输出口径

```
iter_data.json
├── files[]        # 每个 xlsx：识别到的案例表名、表头行、含图工作表、未识别列
├── cases[]        # 每条：模块/测试项/标题/级别/步骤/输出/实际输出/状态/截图引用/图片/告警
├── shot_spans{}   # 每个含图工作表的锚点区间
└── warnings[]     # 未识别列、未解析引用
```

### 0.3 验收清单

- [ ] `cases` 条数与该 xlsx 案例行数一致（抽样 3 条核对行号）
- [ ] 每个文件打印的 `unmapped` 为空，或已知列的误识别已向用户说明
- [ ] `cases with images` 数量与人工抽查"截图对应行数列非空"的案例数一致
- [ ] 若用户提供了历史报告作参照，抽查 2 个引用行（如 A8/A37）解析到的图片与历史报告截图一致

## 阶段 1：范围确认（人工，不可跳过）

问用户三件事：
1. **排除哪些模块**（历史口径：纯理算计算逻辑、通知书类不写；页面显示类要写——但**每次由用户给清单**，不内置判定）
2. **每模块几个案例**（2 或 3）
3. **无截图引用的模块怎么处理**：补截图（用户自己截）/ 用"实际输出"数据写文字 / 暂不写

给用户看的盘点表格式：

| 模块 | 案例数 | 带截图案例数 | 测试项数 |
|------|--------|--------------|----------|
| … | … | … | … |

## 阶段 2：选案

### 2.1 "重要"案例优先级

1. 正反例对照（能/不能、内部/外部、是/否）
2. 核心规则基线（最小配置、正常路径）
3. 覆盖不同测试项（同一模块内尽量不重复测试项）
4. 阻断与非阻断校验成对时各取一个
5. 字段展示类选"新增字段最全"的那一条

### 2.2 产出 picks.json 并抽图

```bash
python <skill>/scripts/pick_cases.py --data iter_data.json --picks picks.json \
    --outdir report_assets --out selected.json
```

- `rows` 按案例表行号（同一模块内定位，避免多文件行号冲突）
- `nos` 按测试案例编号（更稳妥，推荐）
- 输出会标记 `IMG`（有图）/`DUP`（与前面案例共用同一图）/`---`（无图）
- 共用同一图的第 2 个案例：报告里不重复嵌图，描述末尾加"（执行截图同上）"

### 2.3 验收清单

- [ ] 每个选中案例都有图片或明确的处置口径（同上/待补充/文字描述）
- [ ] `DUP` 案例已规划"（执行截图同上）"
- [ ] 无图案例的描述包含"实际输出"里的关键单号/金额（有则写，无则只写结论）

## 阶段 3：取证核验（质量闸门）

1. **逐张打开核对**：案号、页面字段、提示文案与案例描述一致才可用；不一致→换同组备选
2. 无引用模块排查隐藏图：
```bash
python <skill>/scripts/contact_sheet.py --data iter_data.json --media-dir all_images \
    --selected selected.json --outdir scan
```
3. 结论写进交付说明：哪些模块/案例没有截图、原因、待补充位置

## 阶段 4：组版

### 4.1 写 report.json

结构见 `references/report-spec.md`；示例见 `assets/report_spec.example.json`。

每个案例的 `label` 只写标题（编号会被脚本剥离），`desc` 用原始字段组织：
- 有"实际输出"数据 → "……（保单号：XX，案件号：XX）"
- 纯字段展示 → "字段必录/文本展示，自动带出【立案登记】录入值，字段展示正确"
- 纯阻断校验 → "点击【保存】触发阻断提示'……'"

表头口径：
- `req_title`：需求编号+名称
- `tester` / `modules`：**留空**（人工填）
- `verdict` / `env`：模板固定值 `测试通过` / `DEV测试环境 localhost:8080`

### 4.2 生成

```bash
python <skill>/scripts/build_report.py --spec report.json --out "【自测报告】RCP-XXXX-…-已填写.docx"
```

页面几何（内置模板固定）：A4，左右边距 0.75cm，可用宽度 19.5cm；截图宽 6999605 EMU（约 19.44cm）。
分页：节标题 keepNext；截图段 keepLines + 居中；**案例正文不加 keepNext**（见 pitfalls 21）。

### 4.3 与格式基准对齐（用户给了 `format_ref` 时必做）

```bash
python <skill>/scripts/inspect_ref.py  "基准报告.docx"
python <skill>/scripts/inspect_table.py "基准报告.docx"
python <skill>/scripts/make_template.py          # 把基准的表格几何写进模板
python <skill>/scripts/compare_fmt.py "生成的报告.docx" "基准报告.docx"
```

`compare_fmt.py` 必须全部一致：页面几何、表头每格的字体/字号/加粗/颜色、正文各级字号分布、截图宽度。

### 4.4 验收清单

- [ ] 表头：需求编号/名称、提交日期（默认当天）正确；**测试人/模块留空**；测试结论绿色、测试环境为模板固定值
- [ ] 表头字体：微软雅黑 10.5pt；模块值 9pt 加粗；测试环境值 10pt 加粗
- [ ] 正文：节标题 → 功能说明 → 案例（加粗标签+描述）→ 截图，顺序一致
- [ ] 正文无 `RCP-\d+-\d+` 案例编号
- [ ] 图片数量 = 案例中带 image 的数量（共用图不重复计入）
- [ ] 截图宽度 6999605 EMU、居中、无溢出

## 阶段 5：渲染验收

```bash
python <skill>/scripts/render_docx.py --docx "…-已填写.docx" --outdir render
```

逐页自查清单（visual-judge 不可用时）：
- [ ] 图片无溢出页边距 / 截断 / 变形 / 与文字重叠
- [ ] 无"标题在页底、内容全在下一页"的孤立标题
- [ ] 节编号 1.1 → 1.N 连续且按序
- [ ] 每节"案例数/图片数"与规划一致（含"同上""待补充"的例外）
- [ ] 无乱码、表格内容完整

## 阶段 6：交付

给用户的说明固定包含：
1. 输出文件路径 + 页数 + 节数/案例数/截图数
2. 每节案例清单（模块 → 案例标题）
3. **无截图模块的处置说明**（待补充位置、用实际输出代替的部分）
4. `report.json` 留档路径（便于下一迭代复用改版）
5. 可快速改版的口径（改 report.json 重跑 build_report 即可）
