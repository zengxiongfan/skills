# 操作手册写作规范（writing-guide）

每个需求点统一采用"功能描述 + 操作方法"两段式，编号由 build 脚本自动生成，content.py 只写标题文字。

## 一、章节骨架

单本手册：

```
h1('1  手册说明')                      # 可选：背景/范围/需求点对照表
h2('2  需求点一：<需求点名称>')          # 每个需求点一章
  h3('2.1  功能描述')
  h3('2.2  操作方法')
h2('3  需求点二：...')
...
h1('N  附录：截图补充清单')              # 由 manifest.appendix 自动生成，content 不写
```

整合版由 build_merge 自动生成 `P  <部分标题>` + `P.k  需求点` + `P.k.j  功能描述/操作方法`，无需手写。

## 二、功能描述怎么写

必备四类信息，按顺序：

1. **功能位置**：`para(doc, '功能位置：【理赔管理】-【案件审核】。')`
2. **现状 / 本次调整**（有二义时）：bullets 两条对照
3. **规则要点**：bullets，一条一个规则；关键词用 `**加粗**`
4. **字段/校验表**：`table(doc, ['字段说明','是否必录','字段格式','备注说明'], rows, widths=[3.2,1.8,2.6,8.4], font_size=8.5)`
5. 需要时补 `note(doc, '...')` 与举例 `para/bullets`

写作要求：
- 只写"系统做什么、业务看到什么"，不复述需求原文的长段落；
- 提示语/校验文案以**系统实际截图为准**；与需求不一致时在 note 里注明"SIT 截图提示语为…，以系统实际为准"；
- 不编造未在需求/截图/测试案例中出现的字段和按钮。

## 三、操作方法怎么写

`steps(doc, [...])` 输出 `1、2、3、`：

- 一步一个动作，动词开头（进入/选择/录入/点击/核对/提交）；
- 菜单与按钮用【】（如【福利管理】-【保单理赔福利录入】、点击【保存】）；
- 最后一步通常是"核对结果/继续后续流程"；
- 涉及校验的场景，写"按提示调整后重新保存"，不要罗列所有提示语（提示语放功能描述）。

示例：

```python
steps(doc, [
    '进入【福利管理】-【保单理赔福利录入】，查询并选中目标保单，点击【保单理赔福利维护】；',
    '在左侧福利树选中需要设置的层级；',
    '点击【新增】，将"要素类型"选择为"**公共保额**"；',
    '按字段说明录入福利值、公共保额险种、公共保额责任、保单范围；',
    '点击【新增】/【修改】保存；按校验提示调整后重试。',
])
```

## 四、图与图注

```python
figure(doc, os.path.join(ASSETS, 'fig2_1_plan_level.png'),
       '方案层维护"公共保额"要素', '2', 6.3)
```

- 图号自动生成 `图{章节}-{序号}`；chapter 传需求点号（单本传 '2'，整合由脚本重编为 `图P.k-n`）；
- 图注格式：`页面/入口——操作点`，不超过 30 字；
- 缺图用 `placeholder(doc, '建议补充：<场景>截图（测试案例中未提供）。')`，由 build 自动汇总进附录（若配置）。

## 五、表格规范

- 表头首行，`font_size=8.5~9`，总宽不超过 15cm；
- 列名简洁：字段说明 / 是否必录 / 字段格式 / 枚举值 / 备注说明；
- 单元格内换行用 `\n`（table() 会原样写入）；
- 大表（>15 行）拆分或转为 bullets。

## 六、常用句式

- 现状/调整：`现状：…；调整后：…`
- 校验：`点击【X】后，系统校验…，否则阻断提示：…`
- 生效范围：`仅【A】支持修改，其他页面只读`
- 数据范围：`数据范围：仅含…的…`
- 提示：`note(doc, '本次不涉及…')`

## 七、禁止项

- 不写需求文档中的内部批注（如"待确认""--王少昆"）；
- 不把需求大段文字直接搬进手册；
- 不使用"可能/大概/建议系统"等不确定表述描述已定规则；
- 不在 content.py 里硬编码图号、章节号（由引擎/构建脚本生成）。
