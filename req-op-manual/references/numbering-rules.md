# 编号规则（numbering-rules）

## 一、单本手册（single）

| 对象 | 规则 | 示例 |
|---|---|---|
| 一级标题 | 第1章固定为"1  手册说明"（可选）；需求点从 2 开始 | `2  需求点一：公共保额设置` |
| 二级标题 | `{章号}.1  功能描述` / `{章号}.2  操作方法` | `2.1  功能描述` |
| 图号 | `图{章号}-{序号}`，章内连续 | `图2-1` |
| 附录 | 最后一章，标题如"14  附录：截图补充清单" | — |
| 文件命名 | `<需求号>--<需求名>操作手册V<版本>.docx` | `RCP-15795--...操作手册V1.0.docx` |

## 二、整合版（merge）

| 对象 | 规则 | 示例 |
|---|---|---|
| 部分（H1） | `{P}  {部分标题}`，P 从 1 起 | `1  RCP-15793 · 第一个迭代——福利自动映射规则` |
| 需求点（H2） | `{P}.{k}  {需求点标题}`，k 为部分内序号 | `3.2  需求点二：理算规则调整…` |
| 子节（H3） | `{P}.{k}.{j}  功能描述/操作方法` | `3.2.1  功能描述` |
| 图号 | `图{P}.{k}-{n}`，按需求点计数 | `图3.2-1` |
| 附录（H1） | 六部分之后，如 `7  附录：截图补充清单` | — |
| 附录"对应章节" | 旧 `c.x` → 新 `P.(c-1).x`（旧第1章为手册说明） | 旧 `3.2` → 新 `5.2.2` |

merge 时 build_merge 自动完成：跳过各源手册封面/文档信息/目录/手册说明、H1→H2、H2→H3、图注重编号、附录汇总重编号。

## 三、vnext（升版本）

- 输出新文件名（含新版本号），**不覆盖旧文件**；
- 修订记录追加一行：版本、作者、修订详情（说明本次改了什么）、日期；
- 封面/页眉中的版本号同步为新版本；
- 若基于整合版改版：复用 merge 流程 + `drop_chapters` 去除指定章节（如"手册说明"）；
- 若基于单本改版：复制 manifest + content.py，修改后重新 build。

## 四、目录

- 单本 simple 样式：静态目录条目由 manifest.toc 提供，格式 `[编号, 标题]`；
- 整合版 / corporate 样式：使用 Word TOC 域（`TOC \o "1-2"`），生成后由 verify 或 `--update-toc` 调用 Word 更新页码；
- TOC 层级默认 1-2（部分 + 需求点），如需列出功能描述/操作方法可改为 `1-3`。
